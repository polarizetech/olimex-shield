# docs-site/ — this repository's docs site

Generated by [automatic-documentation-site](https://github.com/polarizetech/automatic-documentation-site)
from [`../docs-site.toml`](../docs-site.toml). Nothing on the site is written by hand: a page is
fixed by fixing the Markdown file, docstring or story it names.

```bash
pip install "git+https://github.com/polarizetech/automatic-documentation-site@v0.2.1"
docsite dev .        # build, open the browser, rebuild and reload as you edit
docsite build .      # → docs-site/dist; open docs-site/dist/index.html (no server needed)
```

`.github/workflows/docs-site.yml` rebuilds the site on every push to `main` and deploys it to
GitHub Pages.

## Stories

`stories/*.py` are real calls into `apps/server` and `apps/web`, run at build time; each
function body is the example shown on the page.

**Stories use synthetic or modelled inputs only, never a recording of a person.** The synthetic
signals are seeded and generated in the story, so each has a known right answer and the story
is also a check. A synthetic story carries no MEASURED badge; a story about the front-end model
is badged MODELLED.

A story that raises is shown on its page as failed. A check inside a story that does not hold
is shown as it came out; it is not edited to pass.
